# 知識圖譜對接更新 SOP——新訪談集／新觀點怎麼接進去

> 你做完 v1.0 之後，那個人會繼續產出新內容（出新書、新訪談、新觀點）。
>
> **錯誤做法**：每次都建一個獨立檔案，最後變成一堆孤立 silo。
>
> **正確做法**：按主題拆散到既有 references。這樣讀者搜「槓桿」這個主題會自動拿到 v1.0 + v2.0 + v3.0 的累積觀點。
>
> 這條 SOP 從 Naval 技能包跨集對接的實戰浮現出來。9 步走完。

---

## 兩種更新姿態

### 孤立附件（錯）

```
references/
├── 01-leverage.md
├── 02-thinking.md
├── 03-naval-2025-interview.md   ← 新訪談集獨立成檔
├── 04-naval-2026-interview.md   ← 又一集獨立成檔
└── ...
```

問題：讀者搜「槓桿」時不會看到 03、04 裡的最新觀點，因為它們是孤立 silo。

### 知識圖譜對接（對）

```
references/
├── 01-leverage.md
│   ├── 原本的書本內容
│   ├── ## 2025 訪談延伸：純軟體不可投資
│   └── ## 2026 訪談延伸：個人 App Store
├── 02-thinking.md
│   ├── 原本的書本內容
│   └── ## 2025 訪談延伸：AI 取悅你
└── 01g-vibe-coding-2026訪談.md  ← 整集主檔（給想看完整脈絡的人）
```

每個訪談集**按主題拆散**到既有檔案末尾，加「## YYYY 訪談延伸」段落。同時保留一份整集主檔給想看脈絡的人。

## 9 步 SOP

### Step 0（建議）：先做模擬驗證再決定要不要進 SOP

新素材一出，**不要直接動手補**。先用 `08-validation-via-simulation.md` 的方法做一輪模擬比對：

1. 從新素材挑一個主題
2. 讓現有分身針對這題模擬回答（不看新素材）
3. 匯入新素材逐段比對
4. 五維打分（D1–D5）

**判讀**：
- 整體 8.0+ → 不必進這套 SOP，分身已經夠
- 6.0–7.9 → 進 9 步 SOP，但只補低分段落對應的 reference
- < 6.0 → 先回頭看是不是 SKILL.md 層級有系統性偏誤（保守、哲學化、愛給金句），修完 SKILL.md 再進 SOP

這個前置步驟讓更新從「無腦補料」升級為「先診斷再開藥」。

### Step 0.5：先建立來源節點，不直接改人格

新素材通過 Step 0 後，先把它當成「來源節點」，不要直接改人格語氣或判斷規則。

來源節點至少記錄：

| 欄位 | 內容 |
|---|---|
| 來源標記 | `[2026訪談]`、`[書]`、`[課程逐字稿]` |
| 原始位置 | URL、檔案路徑、章節、頁碼、時間戳 |
| 日期 | 發布日或取得日 |
| 主題 | 3-8 個主要主題 |
| 證據層級 | A/B/C/D |
| 對接位置 | 應接到哪些既有 reference |
| 更新影響 | 只補資料／改回答工作流／改 anti-patterns／改 SKILL.md |

判斷原則：
- 來源節點先成立，才改人格設定
- C 層推導可以進思維引擎，但要標明「依其思路推導」
- D 層材料不可直接推動人格改版
- 新素材若只讓回答更炫，但不能提升可控性、穩定性或來源追溯，不急著更新

### Step 1. 抓日期、定來源標記

新訪談集進來，第一件事：

- **確切日期**（YouTube：用 `curl + grep '"uploadDate"'` 抓）
- **定來源標記**：
  - 第一集：`[書]` 或 `[2025訪談]`
  - 第二集：`[2025訪談II]` 或 `[2026訪談]`
  - 編號規則：年份 + 序號（同年第二集就 II、III、IV）

### Step 2. 盤點主題 → 決定對接到哪幾個既有 references

讀完整集，列一張**對接表**：

| 章節主題 | 對接到既有檔案 | 橋接邏輯（這集怎麼跟既有原則接上）|
|---|---|---|
| 純軟體不可投資 | `01c-leverage` | 「程式碼槓桿」的最新極致 |
| AI 太想取悅你 | `02a-clear-thinking` | 「自我看不見現實」的 AI 時代驗證 |
| ... | ... | ... |

通常 5-8 個對接點。少於 3 個表示這集太薄；多於 10 個表示你還沒分清主題。

每個對接點也要回答：
- 它補的是既有缺口，還是只是新增趣味材料？
- 它會不會改變既有判斷原則？
- 它是否會新增或修正 anti-patterns？
- 它是否需要更新一頁 cheatsheet？

### Step 3. 建主檔（含對接表）

新檔案命名格式：`01X-集名-YYYY訪談N.md`（例 `01g-Vibe-Coding-2026訪談.md`、`01h-In-the-Arena-2025訪談II.md`）。

主檔結構：

```markdown
# 集名 — YYYY 年訪談 N

> 話題涵蓋：[簡述]
>
> **這集是 [人物] 對 [核心既有原則] 的最新延伸。** 各章節對接到既有檔案：
>
> | 既有檔案 | 對接章節 |
> |---|---|
> | `01c-...` | 第 X 章（XXX）|
> ...

---

## 來源
[YYYY訪談N] = ...

完整章節時間軸：...

---

## 一、[章節 1]
[2025訪談II]
...
```

主檔是「整集精華 + 章節對接表」，給想看脈絡的人。

### Step 4. 既有檔末尾加延伸段

對應到的每個既有檔案末尾加：

```markdown
---

## YYYY 訪談 N 延伸：[標題] `[YYYY訪談N]`

> 詳見 `01X-集名-YYYY訪談N.md` 第 X 章。[1 句橋接邏輯——這集怎麼跟原本原則接上]

### [小段標題 1]
...

### [小段標題 2]
...

---
```

**重點**：

- 開頭一定要有 `> 詳見 01X-... 第 X 章。[橋接邏輯]`
- 橋接邏輯講「這集跟既有原則的關係」，不是新觀點空降
- 結尾用 `---` 分隔，避免跟下一段混淆

### Step 5. 雙檢索更新（線性 + 話題）

`00-index.md` 兩處更新：

**更新 A：來源標記區**

```markdown
來源標記：[書] = ... ／[2025訪談] = ... ／**[2025訪談II] = ... ／[2026訪談] = ...**
```

**更新 B：每個既有主題下加 [YYYY訪談N] bullet**

讓搜「槓桿」這個主題的人會看到新訪談集的相關 bullet：

```markdown
### 槓桿、當責、股權 → `01c-leverage.md`
- 三種槓桿：勞力、資本、程式碼與媒體 [書]
- ...
- 純軟體不可投資 [2026訪談]   ← 新加
- 個人 App Store [2026訪談]   ← 新加
```

**更新 C：新增獨立主題段（給整集主檔露出）**

```markdown
### Vibe Coding 與軟體革命 → `01g-vibe-coding-2026訪談.md`
- [整集核心 bullet 列表]
```

**更新 D：話題對照表加問句**

```markdown
| Vibe Coding 是什麼 | `01g-vibe-coding-2026訪談.md` |
| 跟 AI 協作要注意什麼 | `01g-...` / `02a-clear-thinking` |
```

### Step 6. SKILL.md 加來源定義、話題路由

SKILL.md 兩處更新：

**A. 版本號**：v2.1 → v2.2

**B. 來源標記區**：

```markdown
`[2025訪談II]` = 2025 年 10 月 14 日，Naval Podcast，「In the Arena」...
```

**C. References 清單**：

```
├── 01g-vibe-coding-2026訪談.md       2026 訪談主檔
├── 01h-life-in-the-arena-2025訪談II.md  2025 訪談 II 主檔
```

**D. 話題路由**：把新主檔加進路由表

### Step 7. 語言政策：本體只維護中文（2026-07-30 改，江江拍板）

**技能包與人格設定檔的本體只維護中文，不做雙語對齊版。**

理由：雙語對齊等於同一份內容維護兩份，實務上英文版必然落後。2026-07-30 核對時，persona 英文版已落後中文版十條核心原則、公開 repo 停在三個月前。**落後的版本比沒有更糟**，因為它會給讀者過時的規則。

公開 repo、介紹頁與教學入口也只維護中文版，不再提供英文入口或英文摘要。

所以更新時：

1. 內容有更新 → 只改中文正本，不找英文對應檔。
2. 架構有變動（新增區塊、原則條數變化、新機制）→ 同步更新公開 repo 與介紹頁的中文版架構說明。
3. 既有的英文版技能包 → 退場，不再同步（`persona-mind-distiller-en` 於 2026-07-30 退場）。

### Step 8. 同一人格存在多處時：單一正本，不做人工 cp 同步（2026-07-30 改）

**一個人格只能有一份內容正本。** 其他位置一律是生成物或薄殼引用，不得用 `cp` 批次維護多份「各自都能編輯」的副本。理由：那正是 2026-07-16 立的真相分身禁令要禁的事，改一份漏兩份是必然，不是意外。

範例：Naval 設定檔曾同時存在四處（中文技能包、英文技能包、NPC 客座講師系統、GitHub 部署版）。改成：

- **內容正本**＝`_agent/skills/naval-ravikant/`
- NPC 系統與 GitHub 部署版＝從正本生成，或只放指針，不各自編輯
- 英文技能包＝依 Step 7 退場

確實需要人工同步的例外（目標系統格式不同、無法自動生成）走**受控人工同步登記制**：登記觸發點、負責人、驗證方式與衝突時誰優先，記進 `knowledge-base-health-check` 的機制清單，不靠記憶維護。

衍生系統自己的主檔（例如 NPC 主檔的關鍵字、附件表、話題地圖）是它自己的內容，照它的流程更新，不算副本。

### Step 9. 備份 + 心智圖

**備份**：

```bash
TS=$(TZ=Asia/Taipei date +"%Y-%m-%d-%H%M")
cp -R "_agent/skills/[技能包名]/" "<你的備份庫>/技能包備份/$TS [技能包名] vX.X/"
```

技能包、AI 辦公室、系統規則、重要 workflow 的備份預設放備份庫，不放主庫。這是為了讓主庫保持工作區語意，備份庫負責備份與回滾。

**心智圖**：`_agent/技能包心智圖.md` 找到對應條目，更新版本號跟更新摘要：

```markdown
- [技能包名]（`_agent/skills/...`）
  - vX.X（YYYY-MM-DD）：加入 [YYYY訪談N] 來源，新增 01X-...，01a/01c/02a 各加延伸段
  - 雙軌版；XX reference 檔
```

```
[新訪談集進來]
      ↓
Step 1. 抓日期、定來源標記
      ↓

      ↓
Step 3. 建主檔（01X-...）
      ↓

      ↓

      ↓

      ↓

      ↓

      ↓
Step 9. 備份 + 心智圖
      ↓
[完成]
```

## 常見錯誤

### 錯誤 1：直接建獨立檔案

新集進來建 `15-vibe-coding-2026.md` 就放進 references，沒對接到既有檔。
**結果**：讀者搜既有主題看不到新觀點。
**解法**：按 Step 4 對接到既有檔末尾。

### 錯誤 2：橋接邏輯是空降

「## 2026 訪談延伸」之後直接開始講新內容，沒解釋這集跟原本原則的關係。
**結果**：讀者讀到延伸段莫名其妙、不理解為什麼放這裡。
**解法**：每個延伸段開頭一定要有「這集跟既有原則 X 的關係是 Y」。

### 錯誤 3：架構改了，公開中文版介紹沒一起更新

中文版升版後，公開 README 或介紹頁仍沿用舊區塊數與舊名詞。
**結果**：讀者看到的介紹跟實際技能包不一致。
**解法**：Step 7 同步核對中文正本、公開 README 與相關介紹頁。

### 錯誤 4：主檔太薄、沒有對接表

整集主檔只是 transcript 重貼，沒有開頭的「對接表」。
**結果**：讀者看不到這集跟既有原則的整體關係。
**解法**：Step 3 強制在主檔開頭加對接表（5-8 個對接點）。

## 提醒

這個 SOP 第一次跑會很慢（4-8 小時）。第二次以後會越來越快（1-3 小時），因為你已經熟悉這個人格的對接結構。

**效率關鍵：對接表寫好，後面就是體力活。** 不要急著動筆，先把 Step 2 的對接表想清楚。
